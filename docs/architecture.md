# Architecture today

The program is a local editor plus a play page. Both are webpack bundles. An Express process serves them and stores JSON on disk. There is one local project in `data/project.json` holding many maps; the editor and play page open one map at a time, chosen by `?map=<id>`. `src/engine` draws a map; both pages call it.

```
src/
  Client/     browser UI and the play page
  domain/     pure types and rules: coordinates, grid, rect, ids, project, tileset, map (metatile grids, collision, elevation), movement (the player's cell-to-cell step), collision (what a step may enter), connection (seams between map edges), warp (cell events: warps, signs, item, NPC, and heal-point events), interact (what the player faces), dialog (pages of text with choices), flags (story switches and the session's memory of them), item (catalog, bag, one-time pickup), creature (species, moves, a party of up to six), encounter (grass tables, the battle seam), sight (a trainer's line of sight), battle-data (damage classes, the type chart), battle (one creature against one: damage, accuracy, order, outcome), experience (the level curve and growth), random (the `Random` source type), save (the session snapshot a save file holds), sprite (idle and walk frames per direction), history (undo stack). No DOM, no Express.
  engine/     renderFrame over a DrawPort, Scene, and the frame loop. No DOM; the browser adapts a canvas context.
  Model/      shared types: the read-only legacy placement model, user data, sprite sketches
  Server/     Express routes and JSON files
public/       index.html, play.html, built bundles in dist/
data/         created at runtime: project.json (maps, tile grids, legacy layers), placement images (read-only), user data, sprite models
uploads/      sprite sheet files, stored as <uuid><ext>, plus index.json with the original names
```

`npm run build` compiles both bundles, `npm start` runs Express, `npm run typecheck` runs `tsc --noEmit`, and `npm test` runs `node --test` over `src/**/*.test.ts`. See the root README.

## Boot

Editor (`public/index.html` → `src/Client/index.ts`):

1. Register every custom element in `Client/Constants/components.ts`.
2. On `DOMContentLoaded`, append an `<ide-wrapper>`.
3. `Ide` paints a menu bar (the items do nothing) and a `WorldEditor`.
4. `WorldEditor.setup` loads the project, picks the active map (`Client/Service/active-map.ts`: `?map=` if it exists, else the first map), opens it in `mapSession`, then loads user data and sheets.
5. `WorldEditor.build` mounts the side menu (with `MapSelect` — switch, create, rename, resize, delete; switching and creating reload the page on the chosen map — and `LayerListing`), the tool bar, one `MapCanvas`, and always opens a dialog window. A project with no maps shows an empty state with only the map list. `MapCanvas.setup` decodes the sheets and the map's legacy placements.

Play (`public/play.html` → `src/Client/play.ts`):

1. Load the project and open the session map: `?map=<id>` when the editor's play button asked to try a map, else the start map (`startMap`: `startMapId` when set, else the first map). No maps at all shows a plain message instead of the canvas. Decode every sheet and that map's legacy placements (`Client/Service/load-legacy-placements.ts`).
2. `buildScene` and `renderFrame` on one canvas inside `engine/loop.ts`. The canvas is the 240×160 GBA view at the largest whole scale that fits the window (`engine/camera.ts` `integerScale`), centred on a black body that acts as the letterbox; `cameraFor` keeps the player centred and clamps at the map edge, centring a map smaller than the view.
3. The player starts on the map's `spawn` cell. Held arrow or WASD keys step them cell to cell (`domain/movement.ts`); Shift or X runs; Z or Space interacts with the cell in front (`domain/interact.ts`); Enter or Escape opens the start menu (`engine/menu.ts`). The camera follows. `domain/collision.ts` `canStep` decides what a step may enter (edge, solid, elevation, ledges); a map with no tileset falls back to the edge rule.

## UI model

`Client/Service/Component.ts` is the in-repo element base (T-018). Components implement `setup`, `build`, `css`, and optionally `afterBuild`; `listeners` maps `'selector:event'` to handlers inside the shadow root and `externalListeners` maps bus event names to handlers, which are removed when the element disconnects. `patch()` replaces the built tree and rebinds local listeners. `Dom.makeComponent(Ctor, dataset)` encodes non-string values as JSON onto the element; `parsedDataset` (`Client/Service/parse-dataset.ts`) decodes them back, typed by the component's `Component<TDataset>` parameter. `componentId(Ctor)` is the tag name and keys the saved window rectangles.

The current brush is `Client/Service/brush.ts`: `{ tilesetId, metatileId }` or `null`, held in editor state, never a bitmap. `TilesetPalette` (`Client/Component/Tileset/`) draws one tileset's sheet on the 16 grid, tints solid metatiles red, outlines the selected one, sets the brush on click, toggles `solid` through `projectRepository.setMetatileAttributes`, and authors animation (T-045): “+ Frame” makes the next click on the sheet the selected tile's next frame (later frames are outlined green and numbered), a number field sets the milliseconds per frame, “Clear frames” removes them, and a 32×32 preview cycles with `frameAt` on the wall clock. The repository emits `tileset-changed` after any attribute write and `MapCanvas` rebuilds its scene on it. `SheetViewer`'s "Use as tileset" button reuses the tileset already sliced from that sheet or calls `sliceSheet` and `POST /project/tilesets`, then opens the palette.

`WorldEditor` opens windows and persists view state; map edits do not go through it. `Client/Service/map-session.ts` is the open map plus editor-only state: the paint target (a tile layer, the collision grid, or the elevation grid), the elevation the pencil writes, which layers and overlays are hidden, and the undo history (`domain/history.ts`, a pure capped stack of `TileMap` snapshots). The first `update` after a `save` remembers the grid it replaced; `save` records that snapshot as one undo step, so a whole drag is one step. `undo`/`redo` restore a snapshot and save it; `MapCanvas` binds Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z (or Y) outside text fields. Tools and the layer listing compute the next grid with a pure `domain/map.ts` function (`withTile`, `withRect`, `floodFill`, `addTileLayer`, `removeTileLayer`, `renameTileLayer`, `moveTileLayer`), call `mapSession.update` (live, during a drag) and `mapSession.save` (once, at the end) or `commit` (both), and every listener re-reads the session on `map-session-changed`.

## Data on disk

| File | Written by | Shape |

| `data/project.json` | project, map, tileset, tile-map, and sprite routes | `{ id, name, tilesets: Tileset[], sprites: SpriteDefinition[], playerSpriteId, dialogs: Dialog[], flags: Flag[], items: Item[], startMapId, maps: { id, name, tileMap: TileMap, spawn: Cell, connections: { north?, south?, east?, west? }, events: MapEvent[], layers: Layer[] }[] }`; `layers` is the read-only legacy placement list |

`Project` and `GameMap` live in `domain/project.ts` with pure helpers (`addMap`, `renameMap`, `withMapLayers`, `withMapSpawn`, `withStartMap`, `startMap`, `findMap`). `startMapId` (T-030) is where play begins; `MapSelect`'s flag button sets or clears it, and deleting that map clears it. A map's `connections` (T-031, `domain/connection.ts`) are seams by edge: `{ mapId, offset }`, the offset in cells along the edge added to this map's coordinate (north with offset 3 lines this map's x=0 up with the neighbour's x=3). `crossEdge(size, connections, to, sizeOf)` turns an out-of-bounds step into the neighbour's landing cell (the opposite edge's row or column), or undefined when there is no seam, the neighbour is gone, or the landing cell is off it. `MapSelect`'s link button opens `MapConnectionsForm` for the four edges and turns red when a seam points at a deleted map. A map's `events` (T-032, `domain/warp.ts`) are things on cells that are not tiles; `Warp { kind: 'warp', id, cell, toMapId, toCell, facing }`, `Sign { kind: 'sign', id, cell, dialogId }` (T-034), `ItemEvent { kind: 'item', id, cell, itemId, flagId, metatileId | null }` (T-038), `HealEvent { kind: 'heal', id, cell }` (T-056; nothing to configure, so the picker places it at once), and `NpcEvent { kind: 'npc', id, cell, name, spriteId | null, facing, dialogId | null, behavior, trainer }` (T-042; `npcsOn(events)` lists them; `behavior` is `'still' | 'look' | 'wander'` from T-044, `trainer` is `Trainer { sightRange (1–MAX_SIGHT_RANGE 8), defeatedFlagId, party: Opponent[] } | null` from T-049 — T-057 made the one creature a party of up to `MAX_OPPONENTS` 6 `Opponent { speciesId, level }` lines fought in order; `withEventDefaults` reads a T-049 trainer's `speciesId`/`level` as a party of one (or none) — and `withEventDefaults` gives a person saved before them `still` and `null`). One event of each kind per cell. `warpAt`, `eventsAt`, `withEvent` (one event of each kind per cell, replace by id), `withoutEvent`, and `warpTaken(before, after, events)` — a warp fires only when a step finishes on its cell, so spawning or arriving on one never fires it. In the editor the layer listing's **Events** row is a paint target: a click on an empty cell opens `EventKindPicker` (warp, sign, item, person, or heal point), a click on an event opens its form — `WarpForm` (destination map, arrival cell, facing), `SignForm` (which dialog, with a preview of its first page and a link to the dialog editor), `ItemForm` (which item, which flag remembers it was taken with a “+ New flag” button, which metatile draws it), or `NpcForm` (name, sprite or stand-in, facing, what they do, dialog, and a “Challenges the player” tick that unfolds the trainer fields: sight range, the beaten flag with its own “+ New”, and the party sent out in order, one row of species and level each with “+ Creature” and “×”) — the rubber removes whatever is on the cell, and `Client/Service/draw-events.ts` letters events: purple W, yellow S, green I/N, red H (overlay toggle on the row). A sign is not solid by itself; paint collision on its cell or put it on a solid metatile, as the GBA games do. Dialogs (T-036) live on the project as `dialogs: Dialog[]`; `DialogEditor` (`Client/Component/Dialog/`, the side menu's speech-bubble button) creates, renames, deletes them and edits their pages — one textarea per page, saved on change, with a line count that turns orange when a page wraps past the two lines the play box shows, and up to four choices per page (label plus “ends the conversation” or “→ dialog”) — through `POST/PUT/DELETE /project/dialogs`. `mapSession.commitEvents` writes the list; events are outside the tile undo history. Story flags (T-040, `domain/flags.ts`): the project names them — `Flag { id, name }`, edited in the side menu's flag-button window `FlagsEditor` — and a play session remembers them in `Memory { flags: Id[], variables: { [key]: number } }` (`FieldState.memory`): `hasFlag`/`setFlag`/`clearFlag` on a set of true ids where unknown reads false, and `variable`/`withVariable`/`addToVariable` on a separate number map that never doubles as flags. Plain data, so T-041 writes it as it is (`isMemory` guards the read). Items (T-038, `domain/item.ts`): the project's catalog is `Item { id, name, description }` (`ItemsEditor`, the side menu's box button); the session's `Bag` is a list of `{ itemId, count }` stacks in first-found order (`addToBag`, `bagCount`). An `ItemEvent` on a cell is gone once its `flagId` is set (`isTaken`); `pickUp(bag, memory, event)` adds the item and sets the flag the first time and reports `alreadyTaken` after. In the field session `visibleEvents` hides taken items from the interact resolver, `itemsOnMap` lists the rest for the host — they block the step like a solid cell and `engine/item-actor.ts` draws each as its metatile (or a green cell) between the ground and overhead passes — and interacting with one opens the box with `You found a POTION!` (`foundMessage`). People (T-042): `engine/npc-actor.ts` `npcActor(npc, facing, lookup)` draws an NPC's sprite idle pose for a facing standing on their cell (a blue cell without a sprite) through a `SpriteLookup` the host answers from the project's sprites and decoded sheets; both hosts pass them to `renderFrame` as actors (`MapCanvas.npcActors`, `play.ts`), and in the field session they block the step like a wall. Talking (T-043): interacting with a person opens their dialog (or `(NAME has nothing to say yet.)` when none is set); `faceToward(from, to)` in `domain/interact.ts` is the direction a neighbour turns to, and `FieldState.talkingTo` holds the person's turned facing while the message is open — `npcMover(state, npc)` is what play draws — and clears when the conversation ends so they turn back. Behavior (T-044): `domain/npc-behavior.ts` holds `NpcMotion { eventId, home, mover: Player, pauseMs }` and the pure `tickNpcMotion(motion, behavior, deltaMs, canEnter, random)` — a `look` person turns to a random direction when their pause (1–2.5 s) runs out, a `wander` person tries a step that way instead (refused steps only turn them; `WANDER_RADIUS` keeps them within two cells of home), `still` does nothing. `FieldState.people` carries one motion per person on the map (seeded from the events the first frame they are seen, dropped on a transition), `FieldWorld.random` supplies the numbers (`Math.random` in play, fixed sequences in tests), nobody steps onto an item, another person's cells, the player's cells, or off the map, and the player cannot enter a cell a person stands on or is stepping between. While a message, menu, or bag screen is open people only finish the step they are on. `liveEvents(state, events)` places each person at their current resting cell so the interact key finds a wanderer where they actually stand. Creatures (T-047, `domain/creature.ts`): the project holds `species: Species[]` — `{ id, name, types (one or two names), baseStats { hp, attack, defense, specialAttack, specialDefense, speed }, learnset [{ level, moveId }] }` — a `moves: Move[]` catalog `{ id, name, power, accuracy, type, damageClass: 'physical' | 'special' }` (T-052 added the class; `withMoveDefaults` reads older moves as physical; power 0 is a status move the damage function will refuse until a later ticket) and a `typeChart: TypeChart` (`domain/battle-data.ts`: attacking type → defending type → one of `MULTIPLIERS` 0, 0.5, 1, 2; a missing entry is ×1, so the chart stores only the exceptions; `matchup`, `effectiveness(chart, attacking, defendingTypes)` multiplies across a creature's one or two types, `withMatchup` sets or — at ×1 — removes an entry, `typeNames(project)` gathers every type a species, move, or chart row mentions; `PUT /project/type-chart`; the species editor shows it as a grid of selects under the moves, with “+ Type” to name a type before anything carries it), and `starter: { speciesId, level } | null`. A `Creature` is `{ speciesId, level, hp, experience, moves (≤ 4 ids) }` and a `Party` holds at most `MAX_PARTY` 6 (`addToParty` refuses the seventh). The numbers are our own plain rules, written down in the tests and not borrowed from any game: `statAt(base, level) = floor(base × level / 50) + 5`, `maxHpAt = statAt(hp) + level + 10`, `experienceForLevel(level) = level³` (T-054 uses it). `newCreature(species, level)` starts at full HP with the last four learnset moves at or below the level; `isFainted`, `hasAbleCreature`, `damaged`, `healed`; `starterParty(starter, species)` is what a new game carries — `play.ts` passes it to `newField`, `FieldState.party` holds it, and the save keeps it. `SpeciesEditor` (`Client/Component/Creatures/`, the side menu's paw button) edits species, the move catalog, and the starter. Encounters (T-048, `domain/encounter.ts`): a `GameMap` carries `encounters: EncounterTable { rate (percent per step onto grass), entries: [{ speciesId, minLevel, maxLevel, weight }] }`, edited from the map select's seedling button (`EncounterForm`). `rollEncounter(table, party, random)` is pure given the `Random` source: the rate gates it, `pickEntry` is a weighted pick (weight 0 never), then a level in the line's range; it answers a `BattleRequest { party, opponents: [Opponent { speciesId, level }], trainer: null }` or null. The field session rolls when a step finishes in grass (`FieldWorld.isGrassAt`, `encountersOf`), stops the player there, and puts the request in `FieldState.battle` for the host; the host opens the battle scene on it (T-053, below) — a request the scene cannot open because its species is gone from the project is dropped by `dismissBattle` with `Something rustled in the grass, but nothing came out.` (T-056 removed the placeholder runner) — and `afterBattle(state, result: BattleResult { outcome: 'won' | 'lost' | 'fled', party }, world)` consumes the request and opens the box with the ending (`You won!`, `You lost...`, `You got away.`). A win or a flight keeps the party the battle left and a win counts in `memory.variables['battles-won']`. A loss (T-056) puts back the party the request carried — the pre-battle HP, nobody fainted — and sets `FieldState.retreat`: when the box's last page (`You hurried back to safety.`) closes, a fade starts with the pending transition at `FieldState.healPoint`, or at `FieldWorld.home` (the start map's spawn) when no heal point was used yet. A heal point is set by interacting with a `HealEvent`: the party is refilled by species (`healed`), `healPoint = { mapId, cell, facing }` is where the player stood, and the save keeps it (`SavedSession.healPoint`, null for older saves). Battles (T-053, `domain/battle.ts`): `newBattle(request, speciesOf)` puts the party's first able creature (`combatant`: the creature, its species, working stats from `statAt`, `maxHp`) against a fresh one of the first opponent's species; `battleStep(state, choice, data, random)` resolves one whole turn from the player's `BattleChoice` (`{ kind: 'move', moveId }` or `{ kind: 'run' }`, allowed only against a wild creature — `canRun`) — both sides attack in speed order (`playerFirst`: faster, player on a tie), the second only if still standing, the foe picking one of its moves at random (`foeChoice`) — and settles `outcome` on a faint; `log` holds the turn's lines. The damage rule is ours and spelled out in the test: `base = floor(floor(2 × level / 5 + 2) × power × attack / defense / 50) + 2`, then `× 1.5` STAB when the move shares the user's type, `× effectiveness` from the chart, `× roll` of 85–100 %, never below 1 unless immune; the physical or special pair by the move's `damageClass`; power 0 does nothing (`But nothing happened.`); `hits(accuracy, random)` lands on `random × 100 < accuracy`. A win pays experience (T-054, `domain/experience.ts`): `experienceYield(foeLevel) = 12 × level`; `gainExperience(creature, species, amount)` adds it and applies every level the total reaches one at a time (`levelForExperience`: the highest n with n³ ≤ total, capped at 100), each level refilling HP to the new maximum and taking up the learnset's moves for that level while a slot is free (`LevelUp { level, learned, skipped }`); `growthLines` is what the log says (`SPROUT gained 36 EXP. Points!`, `grew to Lv6!`, `learned EMBER!`, `wants to learn X, but has no room.`), and the fighter's working stats are rebuilt from the new level. `battleResult(state)` is the `BattleResult` the field takes back, the fighter — experience, level, moves, HP — written into the party. The scene (`engine/battle-scene.ts`): `BattleSceneState { battle, panel: intro | main | moves | log | done, highlight, lines }`, `advanceBattleScene(scene, input { up, down, interact, cancel }, data, random)` walks intro → FIGHT/RUN → the move list (cancel steps back) → the turn's lines one press each → back to the menu or `done`; `drawBattleScene` paints the 240×160 view — foe status top-left and stand-in top-right, the player's stand-in bottom-left with its status beside it (HP bar green/yellow/red, numbers for the player only), and the message box with the menu as its choices. `play.ts` holds the scene while it runs (`battleScene`), feeds it key edges (`directionPressed` for the cursor, interact, menu key as cancel), and on `done` calls `afterBattle` with `battleResult`. Nothing branches on how the battle was fought. Trainers (T-049, `domain/sight.ts`): `lineOfSight(from, facing, range, blocked)` is the straight run of cells a person sees the way they face, cut short at the first cell `blocked(from, to)` refuses, and `sees(...)` asks whether a target cell is on it. Each frame the player stands still, the field session looks for a trainer on the map — not yet beaten (`hasFlag` on their `defeatedFlagId`), not the one who just challenged (`FieldState.challengedBy`, forgotten when the player next finishes a step, so a lost or fled fight is not refought on the spot), standing, with the player in sight past walls, items, and other people. Found, `FieldState.approach = { eventId }` freezes the player and `approachFrame` walks the trainer one cell at a time toward them; beside them the player turns to meet them and `FieldState.battle` becomes `BattleRequest { party, opponents: trainer.party, trainer: TrainerChallenge { eventId, name, defeatedFlagId } }` — the very same scene — or, with nobody to send out, the trainer just stops there. In the battle (T-057) `BattleState.opponents`/`foeIndex` track the other side: when the foe faints and another line remains whose species the `BattleData.species` list knows, `settle` pays the experience, sends the next one out fresh (`ACE sent out SLUG!` in the log; `The foe` when no trainer named them), and the battle goes on — `outcome` is `won` only once the last one is down, so `battleResult` of an unfinished battle is not a win. The scene's opening line is `NAME wants to battle!`; `afterBattle` on a win sets the defeated flag so they never challenge again (and the save keeps it); a loss takes the same retreat as a wild one and leaves the flag clear. A `GameMap` carries a `spawn` cell (T-026) that defaults to the grid centre and snaps back there when a resize leaves it outside. `Server/services/project-store.ts` reads and writes the file; handlers call a domain helper and write the result. `withProjectDefaults` fills fields an older file lacks, and boot writes the result back once.

A map's grid is a `TileMap` (`domain/map.ts`): `width` and `height` in cells, a `tilesetId`, `layers: TileLayer[]` back to front (each a dense row-major `MetatileId[]` with `kind: 'ground' | 'overhead'`), and `attributes` (`collision[]`, `elevation[]`, `ledge[]`, `grass[]`, `gate[]` on the same index; `ledge` is stored since T-022 and enforced by `domain/collision.ts` since T-028; `grass` (T-048) marks tall grass, painted from the layer listing's green **Grass** row with `withGrass` and shown as a green tint, read by `isGrassAt`; `gate` (T-050) holds `Gate { flagId, openMetatileId | null } | null` per cell — a cut tree, a boulder — placed one at a time from the layer listing's orange **Gates** row through `GateForm` (the flag that opens it, with “+ New flag”, and the metatile shown once open), removed by the rubber, drawn as an orange G; `gateAt`, `withGate`, and `withOpenGates(map, isOpen)`, which swaps each open gate's front-most painted picture for its open metatile — what play draws, never what is stored). A `Tileset` (`domain/tileset.ts`) maps ids to a `sheetId` plus a pixel rectangle and the defaults `solid`, `elevation`, `ledge`, and an optional `animation: TileAnimation { frames: Coordinates[], frameMs }` (T-045) — the extra pictures on the same sheet after the tile's own rectangle; `frameAt(metatile, timeMs)` is the source rectangle for a clock time (frame 0 for the first `frameMs`, then each later frame, round and round) and `frameCount` is one plus the extra frames. `withMetatileAttributes` takes `animation: null` to remove it; `withAddedFrame` builds the next animation at `DEFAULT_FRAME_MS` 250. Id 0 is the empty cell and is never solid. `isBlocked(map, tileset, to, from?)` is the movement rule: outside, painted collision, or any solid metatile blocks; with `from`, a change between two non-zero elevations blocks. `canStep` (and `stepRule`) take an `IsOpen (flagId) => boolean` as well: a gate cell is a wall until it answers true, and with none given every gate is shut. Tilesets are sliced from a sheet (`sliceSheet`, T-019) and edited through the palette. The editor's tools write metatile ids into the active `TileLayer` (T-020); a map without a tileset adopts the brush's tileset on the first stroke, and a brush from a different tileset is refused. `isTileMap` is the server's structural check on a saved grid; `withTileMapDefaults` adds arrays an older file lacks; `resizeGrid`/`resizeTileMap` re-lay every layer and attribute grid for a new size, anchored top-left. Attribute painting (T-022) goes through `withCollision`/`withElevation` with the generic `withCell`, `withCellsRect`, and `floodFillCells`; `attributesAt` reads one cell. Painting an attribute never touches a picture layer.

A legacy placement layer (`Model/Layer.ts`) is:

```ts
{
  uuid, type, name, created_at, is_visible, is_active, order,
  placements: { uuid, coordinate: { x, y }, imageUuid }[]
}
```

Since T-020 nothing writes placements. A map painted before metatiles keeps them and both pages draw them as a frozen background under the tile layers; they cannot be edited or deleted from the UI. `type` is kept as text and ignored. See [decisions/0001-tile-grid.md](decisions/0001-tile-grid.md) and [decisions/0003-assets-on-disk.md](decisions/0003-assets-on-disk.md).

## Draw path

`engine/render.ts` `renderFrame(port, scene, view, actors, timeMs)` is the only code that draws a map. A `View` (`engine/view.ts`) is the camera position in world pixels plus an integer `zoom` (1–4); `worldToScreen`/`screenToWorld` are the only two conversion formulas, and `zoomedAt` changes zoom while keeping the world point under a screen anchor still. A `Scene` (`engine/scene.ts`) is the tile map (hidden layers already left out), its tileset, decoded sheets by id, and the legacy placement layers sorted back to front. A `DrawPort` (`engine/draw-port.ts`) is clear, fill-rect, and draw-image-region; `Client/Service/canvas-draw-port.ts` adapts a `CanvasRenderingContext2D` with smoothing off. Passes are fixed (T-023): legacy placements as a frozen background (back to front; a **lower** `order` paints **in front**, via `Model/draw-order.ts`), then `ground` tile layers in list order, then the actors passed to `renderFrame`, then `overhead` tile layers. An `Actor` (`engine/scene.ts`) is a world rectangle with an optional `SpriteFrame`; without one it is drawn as a filled colour. Actors move every frame so they are a `renderFrame` argument, not part of the cached `Scene`. Cells and placements outside the view are culled. Each tile's source rectangle is `frameAt(metatile, timeMs)`, so animated water cycles on the clock the host passes — play's session clock (`clockMs`, summed from the loop's deltas and running on through fades and menus) or the editor's `performance.now()` — and a host that passes nothing draws first frames. Zoom multiplies draw sizes; smoothing stays off so pixels stay square.

Editor: `MapCanvas` is one element with one `<canvas>` and one `engine/loop.ts` loop. It builds the scene with `Client/Service/build-scene.ts` from `mapSession.visibleTileMap()` and marks it stale on `map-session-changed`. The pointer always lands on it: pencil and rubber call `withTile` per pointer sample and save on mouseup, rectangle previews a span and calls `withRect` on mouseup, fill calls `floodFill` (bounded by the map, not the view) and saves at once. On an attribute target the same tools write 0/1 collision or the chosen elevation (rubber writes 0). `Client/Service/draw-attributes.ts` draws painted collision in red, cells a solid metatile blocks in orange, and non-zero elevation as a tinted, numbered cell; each overlay hides without changing data. The brush is a metatile id; a one-cell ghost canvas previews it. The middle button pans the shared `camera` (`Client/Service/camera.ts`, which holds the `View`); the wheel and the HUD's −/+ buttons zoom toward the cursor or the centre. The HUD (bottom-left) also toggles the grid (`Client/Service/draw-grid.ts` strokes cell borders and the map outline over the frame) and reads out the cell under the cursor. Zoom and the grid flag persist in `user-data.json` (`zoom`, `showGrid`). `Client/Service/pointer-to-world.ts` is the one pointer → world formula and takes the `View`.

Play: `play.ts` builds a scene once and runs the same loop and `renderFrame` at zoom 2. The player is a `domain/movement.ts` `Player`: a cell, a facing, and an optional `Step` (`from`, `to`, `durationMs`, `elapsedMs`). Each frame the host passes `{ direction, running }` — `Client/Service/held-directions.ts` keeps held keys in press order so the newest press wins — and `stepPlayer` advances the step by the frame's milliseconds, then begins the next one if a direction is still held and `CanEnter` allows the target cell. The field session is `engine/field.ts` (T-033): `FieldState { mapId, player, fade, pending, interaction, message, lastDirection, memory, bag, menu, menuChoice, bagScreen, partyScreen, talkingTo, people, party, battle, approach, challengedBy, healPoint, retreat }` and `advanceField(state, input, deltaMs, world)`, where `FieldWorld` answers `sizeOf`, `canEnter(mapId, memory)` (the rule reads the session's flags for gates; `play.ts` rebuilds it, and the drawn scene through `withOpenGates`, only when `memory.flags` changes), `isSolidAt`, `connectionsOf`, `eventsOf`, `pagesOf`, `itemOf` (the play host builds it from the project in `worldOf`). Each frame the player steps under a seam-aware rule — `canEnter` inside the grid, `crossEdge` beyond it onto a non-solid landing cell — then `warpTaken` and a finished step past the edge become a pending `Transition { mapId, cell, facing }` and start a fade (`engine/fade.ts`: `FADE_MS` 200 out, 200 in; `advanceFade` reports `swap` on the frame the screen is black; `fadeOpacity` is 0–1). While a fade runs the player is frozen and input is dropped; at `swap` the state moves to the pending map and cell. The host swaps scenes when `state.mapId` changes (`openMap` in `play.ts`; legacy placements for every map are decoded at boot) and paints `rgba(0,0,0,opacity)` over the frame. `stepFinished(before, after)` is how both warps and seams notice a step completing even when a held key has already chained the next one. `FieldInput` adds `interact` and `menu` (edges: the host sets them on keydown and the next frame consumes them); when pressed while standing, the frame does not move the player and `state.interaction` carries `domain/interact.ts`'s answer for the cell in front — `cellInFront(player)`, `interactionAt(events, cell)` with the priority NPC, then item, then sign; warps are not interactive — for the host to act on. It is cleared the next frame. A sign answer also opens the message box (T-035): `engine/message.ts` is the pure runner — `MessageState { pages, index, highlight }`, `openMessage(pages)`, `advanceMessage(state, resolve)` (the next page; on a page with choices the highlighted choice's dialog opens from its first page through `resolve`, or null ends the conversation; null after the last page), `moveHighlight(state, ±1)` stops at the ends, `wrapText(text, columns)` breaks at spaces and explicit newlines — and while `state.message` is open `advanceField` drops movement, turns a fresh up or down press (`FieldState.lastDirection` makes holding count once) into a cursor move, and confirms on `interact`. Pages come from the project's `dialogs` (`domain/dialog.ts` `Dialog { id, name, pages: DialogPage[] }`, `DialogPage { text, choices: Choice[], setsFlagId? }` (a page that names a flag sets it the frame it is shown — T-050's way for a conversation to open a gate; the dialog editor's “When shown: sets …” row per page), `Choice { label, nextDialogId | null }`, at most `MAX_CHOICES` 4; `withDialogDefaults` reads T-035's bare-string pages) through `world.pagesOf(dialogId)`; a missing dialog shows `(No dialog "id" exists yet.)` so the author can see what to fix. `drawMessageBox(port, state, GBA_VIEW, zoom)` paints the panel along the bottom of the view — border, cream fill, two wrapped lines of 36 columns at a 10 px monospace font, a red ▼ when more pages follow, or the choice box above the right end with a ▶ on the highlighted row — through the new `DrawPort.fillText`, which the canvas adapter maps to the built-in monospace font; play never loads a web font. The start menu (T-046, `engine/menu.ts`) is the same shape: `MENU_ENTRIES` bag, party, save, close; `MenuState { highlight }`, `openMenu`, `moveMenu` (wraps), `selectedEntry`, `drawMenu(port, state, view, zoom, enabled)` in the top-right corner with disabled entries greyed. `input.menu` opens it when the player stands with no message up (and closes it again); while `state.menu` is open movement is dropped, a fresh up/down press moves the cursor, and `interact` puts the entry in `state.menuChoice` for the host — Close (or the menu key) closes it, other entries leave it open until their screens exist. `play.ts` keeps `ENABLED_ENTRIES` for what opens today. Bag (T-039, `engine/bag-screen.ts`) opens `state.bagScreen` over the menu: `drawBagScreen(port, bag, itemOf, state, view, zoom)` fills the view with a list panel of `NAME ×count` rows (scrolling `BAG_ROWS` at a time via `firstVisibleRow`) and a description panel for the highlighted stack; up/down move the cursor (`moveBagCursor`, clamped), the menu key — or the interact key, since nothing can be done with an item yet — steps back to the menu. Party (T-055, `engine/party-screen.ts`) opens `state.partyScreen` the same way: `drawPartyScreen(port, party, lookup { speciesOf, moveName }, state, view, zoom)` lists the party on the left (cursor, name, level, HP bar and numbers; a fainted creature greyed) and names the highlighted creature's types, moves, and experience on the right; up/down move the cursor (`movePartyCursor`, clamped), either key steps back to the menu, and the field waits where the player stood. Nothing is reordered here. Save (T-041): `domain/save.ts` `SavedSession { mapId, cell, facing, memory, bag }` — never the map — and `SaveDocument { version: 1, slots: [{ …session, savedAt }] }`; `serializeSave` and `parseSave` (a result, never a partial session: wrong version, no slot, or a bad field each give a reason). `snapshotField(state)` takes the standing cell (a step in progress saves as its target), `restoreField(session)` resumes with memory, bag, and party (a save written before parties resumes with nobody), `afterSave` closes the menu and says “Saved the game.” The host writes through `Client/Service/Repository/SaveRepository.ts` when `menuChoice` is `save`. At boot, unless the editor asked for `?map=`, an existing save poses “A saved game was found.” with Continue / New game drawn by the message box on black (`askToContinue`); New game deletes the save. `stepRule`: `canStep(map, tileset, from, to)` refuses the map edge and solid cells (`isSolid`), treats a ledge as one-way — its direction is the way you hop it, so you enter a ledge cell only moving that way and cannot leave it against that way (`ledgeAt`: painted attribute, else the front metatile's) — and blocks a change between two non-zero elevations except across a ledge taken the right way. Facing changes at once even when the step cannot start; a press during a step only turns the player. Walk is `WALK_MS_PER_CELL` (267), run `RUN_MS_PER_CELL` (133), matching the GBA's 16 and 8 frames per cell. `playerPixel` interpolates `from → to` for drawing. `engine/camera.ts` (T-029) is the play camera: `GBA_VIEW` is 240×160 world pixels, `integerScale(window)` picks the scale, and `cameraFor(focus, view, mapPixels)` returns the whole-pixel top-left that centres the player's cell, clamped to `[0, map − view]` per axis, or `(map − view) / 2` (negative) when the map is smaller than the view on that axis. The editor keeps its free `Client/Service/camera.ts`.

Sprites (T-027): a `SpriteDefinition` (`domain/sprite.ts`) is a sheet id, a frame size, and per direction an `idle` rectangle and a `walk` list of rectangles on that sheet. `pickFrame(definition, direction, phase, idle)` is the whole animation rule: idle (or an empty cycle) shows the idle pose; otherwise the step's phase indexes the walk list evenly. `engine/player-actor.ts` `playerActor(player, sprite, image)` turns the `Player` into the `Actor` `renderFrame` draws — the frame for `facing` and `stepProgress`, standing on its cell so a 16×32 frame overhangs the cell above — or a red cell when the project has no player sprite. The project holds `sprites[]` and `playerSpriteId`; `SpriteEditor` (`Client/Component/Sprite/`, the side menu's walking-figure button) creates sprites from an imported sheet, lets the author pick a slot (a direction's idle or a walk frame) and click a frame on the sheet grid to assign it, previews the walk cycle, saves every change, and marks one sprite as the player's.

JSON reads and writes are synchronous. `writeJson` writes a `.tmp` sibling and renames it over the target, so a reader never sees a torn document. It does not lock: two overlapping PATCHes still race on read-modify-write (last write wins), which one server process and one editor tab keep rare.

## Target shape

This is the direction. It is not a request to move every file in one change. Tickets T-012 through T-018 do it in slices.

```
src/
  domain/     types and pure rules: maps, collision, warps, flags, inventory
  engine/     loop, input, camera, actors, drawing against a small canvas port
  editor/     custom elements that call domain and engine
  server/     HTTP and the file store
```

`domain/` and most of `engine/` must run under `node` tests with no browser. Drawing takes an interface the browser implements with a `CanvasRenderingContext2D`.

## Persistence target

One project directory, chosen explicitly, containing JSON for structure and binary files for pixels. The editor can still be single-user and local. It cannot keep storing the pictures inside the structure. See [decisions/0003-assets-on-disk.md](decisions/0003-assets-on-disk.md).
